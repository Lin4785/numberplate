# 机动车号牌互联网选号系统（仿真）

一个开箱即用的车牌选号项目：完整实现「互联网选号」业务闭环 —— 号段投放与公示、随机选号、自编选号、
号牌规则校验、预选凭证签发，以及配套的管理后台。

整套系统**零第三方依赖**：后端用 Node 内置的 `node:http` 与 `node:sqlite`，前端是原生 HTML/CSS/JS，
不需要 `npm install`，克隆下来直接就能跑。

## 功能一览

**车主侧（选号大厅）**

| 功能 | 说明 |
| --- | --- |
| 信息确认 | 车主姓名、18 位身份证（含校验位验算）、手机号、VIN（17 位）、车辆型号、号牌种类、发牌机关属地 |
| 随机选号 | 每批随机投放 10 个号码，共 5 批；每批可选 1 个作为备选，备选全局只保留 1 个 |
| 自编选号 | 共 20 次机会；按公示号段逐位编排（数字/字母下拉），也可直接输入序号；被占用即消耗 1 次机会 |
| 规则校验 | 序号位数、可用字符集、字母个数上限、新能源 D/F 首位、禁用字母 I/O |
| 预选凭证 | 选号成功即时生成凭证（凭证号、号牌、车主信息、有效期 3 个自然日），支持打印 |
| 号码池查询 | 查询号码是否已被占用、是否落在已投放号段内，不消耗选号机会 |
| 号段公示 | 公开展示各号段的模板、容量、剩余量与占用率 |

**管理侧（管理后台）**

| 功能 | 说明 |
| --- | --- |
| 数据概览 | 申请总数、完成/进行中/作废、号码池占用、整体占用率、号段占用排行、最近选号记录 |
| 号段管理 | 投放新号段（自动校验模板与号牌种类是否匹配）、启用/停用号段 |
| 号码池 | 按号段/状态/关键字检索已占用号码、人工释放号码、人工标记号码为已占用 |
| 选号记录 | 按申请编号、车主、手机号、号牌号码、状态检索全部选号申请 |

## 快速开始

环境要求：**Node.js ≥ 22.5**（需要内置的 `node:sqlite`；开发时使用 Node 24 验证通过）。

```bash
# 1. 初始化数据库：写入号段、模拟已占用号码、生成少量历史选号记录
npm run seed

# 2. 启动服务
npm start
```

打开浏览器：

| 入口 | 地址 |
| --- | --- |
| 选号大厅 | http://127.0.0.1:5173/ |
| 号码池查询 | http://127.0.0.1:5173/query |
| 管理后台 | http://127.0.0.1:5173/admin |

管理后台默认口令为 `admin123`，生产使用请通过环境变量覆盖：

```bash
NP_ADMIN_PASSWORD=你的口令 npm start
```

其他命令：

```bash
npm test            # 单元测试 + 流程集成测试（node:test，使用独立临时数据库）
npm run smoke       # 端到端冒烟测试（需先启动服务），逐项校验关键接口
npm run lint:actions # 检查前端 data-action 与事件处理函数是否一一对应
npm run test-data   # 生成可直接使用的测试数据（车主/车辆信息 + 配套自编号码）
npm run dev         # 带 --watch 的开发模式
npm run seed        # 重置并重新生成演示数据
```

## 选号规则说明

### 号牌号码的构成

```
号牌号码 = 发牌机关代号（省份简称 + 英文字母）+ 序号
```

序号位数与可用字符随**号牌种类**不同而不同，全部规则集中在 `src/rules.js`：

| 号牌种类 | 底色 | 序号位数 | 序号规则 |
| --- | --- | --- | --- |
| 小型汽车 | 蓝 | 5 | 数字与字母组合，字母不超过 2 位 |
| 大型汽车 | 黄 | 5 | 全数字 |
| 教练汽车 | 黄 | 5 | 全数字 |
| 摩托车 | 黄 | 5 | 字母不超过 1 位 |
| 小型新能源汽车 | 绿 | 6 | 首位固定为 `D`（纯电）或 `F`（非纯电），其余为数字 |
| 大型新能源汽车 | 绿 | 6 | 全数字 |

所有号牌种类都不使用容易混淆的字母 **I、O**。

### 号段模板

一个号段由「发牌机关代号 + 号牌种类 + 序号模板」定义，模板字符含义：

| 字符 | 含义 |
| --- | --- |
| `9` | 该位为数字 0-9 |
| `A` | 该位为字母（24 个，不含 I、O） |
| `*` | 该位为数字或字母 |
| 其他数字/字母 | 该位为固定字面量，例如新能源号段的 `D`、`F` |

例如 `9A999` 表示「第 1 位数字、第 2 位字母、后 3 位数字」；`D99999` 表示「首位固定 D，后 5 位为数字」的新能源号牌。

号段容量按各位候选字符数连乘得出（`99999` = 10 万，`9A999` = 24 万，`999999` = 100 万）。
在号码池中**只存储已被占用的号码**，随机取号时按模板容量做下标采样并按占用情况重试，
因此即使容量达到百万级也不需要预先枚举全部号码。

### 随机选号

1. 点击「随机选号」投放第 1 批 10 个号码，不同批次之间不会重复投放同一个号码。
2. 点击号码即可设为备选；备选在**全局只保留 1 个**，选新的会顶掉旧的。
3. 共 5 批机会，剩余换批次数为 0 时不能再换批。
4. 点击「确认选号」完成，此时系统会对备选号码做一次**原子占用**校验：
   若该号码在投放后已被他人占用，则备选会被清空并提示重新选择。

### 自编选号

1. 选择号段后可按位下拉编排，也可以直接输入序号（自动同步到上方选择器）。
2. 序号格式不合法（位数不足、含 I/O、字母超限、新能源首位不是 D/F）时**返回提示且不消耗机会**。
3. 号码不在本属地已投放号段范围内、或号码已被占用，均**消耗 1 次机会**。
4. 首次通过校验的号码立即占用并生成凭证。

### 并发与一致性

号码占用依赖数据库唯一约束 `UNIQUE (number, plate_type)` 实现原子抢占：
`INSERT ... ON CONFLICT DO NOTHING` 返回 `changes = 1` 即视为抢占成功，否则说明已被占用。
这样无需加锁，也不会出现两个申请同时选中同一号码的情况。

> 注意：号牌号码的唯一性以「号牌种类」为界 —— 蓝牌 `京A·12345` 与黄牌 `京A·12345` 是两个不同的号牌。

## API 一览

### 公开接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 省份简称、号牌种类、规则参数、号段公示数据 |
| GET | `/api/segments?agency=&plateType=` | 号段公示（可按属地与号牌种类过滤） |
| GET | `/api/plates/check?number=&plateType=` | 号码可用性查询 |
| POST | `/api/applications` | 创建选号申请（校验车主与车辆信息） |
| GET | `/api/applications/:code` | 申请详情（含量子批次、自编记录、剩余机会） |
| POST | `/api/applications/:code/random/batch` | 随机投放下一批号码 |
| POST | `/api/applications/:code/random/pick` | 设置备选号牌 `{ batchNo, number }` |
| POST | `/api/applications/:code/random/confirm` | 确认备选号牌并完成选号 |
| POST | `/api/applications/:code/self/attempt` | 提交一次自编选号 `{ number }` |
| POST | `/api/applications/:code/cancel` | 作废申请 |
| GET | `/api/applications/:code/voucher` | 获取预选凭证 |

### 管理接口（需登录，Cookie 会话）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/admin/login` | 登录 `{ password }` |
| POST | `/api/admin/logout` | 退出登录 |
| GET | `/api/admin/session` | 查询登录状态 |
| GET | `/api/admin/overview` | 统计概览 + 号段占用情况 |
| POST | `/api/admin/segments` | 投放新号段 `{ agency, plateType, pattern, name? }` |
| PATCH | `/api/admin/segments/:id` | 启用/停用号段 `{ status }` |
| GET | `/api/admin/plates` | 号码池检索（分页、按号段/状态/关键字过滤） |
| POST | `/api/admin/plates` | `{ action: 'release' \| 'occupy', number, plateType? }` |
| GET | `/api/admin/applications` | 选号记录检索（分页、按状态/关键字过滤） |

## 配置项

通过环境变量覆盖，全部定义在 `src/config.js`：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `NP_HOST` | `127.0.0.1` | 监听地址 |

| `NP_DB_FILE` | `data/numberplate.db` | SQLite 数据文件路径 |
| `NP_ADMIN_PASSWORD` | `admin123` | 管理后台口令 |

选号业务参数（随机批数、每批数量、自编机会数、凭证有效期）集中在 `src/config.js` 的 `RULES` 对象中，可直接调整。

## 数据模型

| 表 | 说明 |
| --- | --- |
| `segments` | 号段：发牌机关、号牌种类、序号模板、启用状态 |
| `plates` | 号码池：**只存已占用号码**，`UNIQUE (number, plate_type)` |
| `applications` | 选号申请：车主车辆信息、状态、结果号码、凭证、已用机会数 |
| `random_batches` | 随机选号批次明细（含备选标记） |
| `self_attempts` | 自编选号尝试记录（成功/失败与原因） |
| `logs` | 业务与后台操作日志 |

## 测试数据

`npm run test-data` 会生成一批**确定可用的**测试数据，并且每条都用项目自身的校验函数复核过：

```bash
npm run test-data                 # 打印 Markdown 表格 + 反面用例（离线可用）
npm run test-data -- --json       # 输出 JSON，便于脚本调用
npm run test-data -- --create     # 把申请写入运行中的服务（需要先 npm start）
npm run test-data -- --verify     # 创建申请后立刻用配套号码真的选一次号
```

输出内容：

1. **车主/车辆信息表** —— 覆盖全部 6 种号牌种类，身份证号经过校验位验算，VIN 符合 17 位规则，
   属地与号牌种类组合都保证有可用号段（否则创建申请会被拒）。
2. **配套的自编号码** —— 直接查库挑出的、当前确实空闲的号码，且**同属地同号牌种类**，提交即可成功。
3. **已被占用的号码** —— 用于测试"号码已被使用"的失败路径。
4. **反面用例** —— 故意写错的输入（身份证校验位、手机号、VIN、序号格式等），
   以及系统实际返回的提示语，用来验证校验逻辑本身。

车主/车辆信息由固定随机种子生成，在相同的数据库状态下每次运行结果完全一致，便于写进文档或自动化脚本。
配套的自编号码需要查库确认是否空闲，因此会随号码占用情况变化。

## 关于本项目的定位

这是一个**业务流程仿真系统**，用于演示、教学或作为二次开发的基础骨架：

- 所有号牌号码与号段均为模拟数据，不具备任何法律效力；
- 未接入真实公安交管数据源，号牌占用状态由初始化脚本生成；
- 初始化数据中的号段占用率是人为设定的（例如沪A 70%、京A 62%），
  并用一批"靓号"（88888、66666、12345 等）固定标记为已占用，让自编选号更接近真实体验；
- 用户侧不做实名认证，申请编号保存在浏览器 `localStorage` 中用于续办；
- 管理后台采用单口令 + Cookie 会话，适合内网演示，正式环境请替换为完善的鉴权方案。

## 二次开发提示

- 新增号牌种类：在 `src/rules.js` 的 `PLATE_TYPES` 中登记，前端会自动读取并渲染选项。
- 调整选号次数：修改 `src/config.js` 的 `RULES`，前后端会同时生效（前端通过 `/api/meta` 获取）。
- 新增号段：优先通过管理后台投放，模板与号牌种类的兼容性会被自动校验。
- 修改前端：`public/` 下就是最终产物，无需构建；刷新页面即可看到改动。
